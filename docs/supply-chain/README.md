# Supply chain: what the APK contains, and what it finds on the device

`vendor-sbom.json` is generated by `tools/vendor-sbom.py` and lists every binary committed verbatim
to this repository, with its SHA-256:

| File | What it is |
| --- | --- |
| `jniLibs/*/libipfs.so` | kubo, built for Android and named `.so` so it ships as a native library (~62 MB per ABI) |
| `jniLibs/*/libacepython.so` | a small launcher for the AceStream Python engine; it links the interpreter the device provides |
| `assets/aceserve/main_android.py` | the engine script that launcher runs |

Not in this file, because it is not in this repository:

- **The AceStream engine and its Python interpreter** (`libpython3.8m.so`) come from the device
  firmware, like the vendor `org.acestream.node.web` app. HaP cannot hash them and does not bundle
  them; the engine only runs where the vendor already provides it.
- **The Android build's own dependencies** (AndroidX, Gradle plugins) are resolved by Gradle and are
  not vendored here.

Regenerate after replacing a binary:

```sh
python3 tools/vendor-sbom.py
python3 tools/vendor-sbom.py --check   # what CI runs
```

The file carries no timestamp on purpose: it changes only when a vendored binary changes.
