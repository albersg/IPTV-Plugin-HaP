# AGENTS.md

## Project Map

This repository builds HaP, a standalone Android IPTV player server (phone
and Android TV) for AceStream (via AceServe/HTTPAceProxy) and IPFS content.
It exposes a native configuration activity, publishes a local `/aio` M3U
provider, prepares local HaP playback, and rewrites local URLs for
Chromecast/LAN playback. It can also run as a StreamVault companion plugin
behind the StreamVault plugin API — that integration is one consumer of HaP,
not its primary purpose.

`docs/architecture/BASELINE.md` is the verified state of every capability
(implemented and tested, pending validation, experimental, proposed, blocked)
with the command or test that proves it. Read it before deciding what is
missing; `odd/BACKLOG.md` is a working list and goes stale faster.

The highest-signal classes are `HapConfigActivity`, `HapBridge`,
`PlaylistCatalog`, `StreamVaultHapPluginService`, `ProxySupervisorService`,
`AceServeRuntime`, and `IpfsRuntime`. Start there when you need architectural
context.

## Main Code Areas

- `app/src/main/java/com/streamvault/plugin/hap/` contains the StreamVault
  plugin surface: `StreamVaultHapPluginService`, `HapConfigActivity`, and
  `PluginContract`.
- `app/src/main/java/com/jopsis/httpaceserveproxy/` contains the HaP runtime
  facade and Android-side proxy logic. `HapBridge` is the central facade;
  `ProxySupervisorService` owns foreground startup/shutdown; `AceServeRuntime`
  prepares and runs the bundled Python/AceServe runtime; `IpfsRuntime` (with
  `IpfsSettings` and `IpfsHealthClient`) prepares and runs the bundled kubo
  (IPFS) daemon on its own supervisor thread, independent of AceServe/proxy.
- `PlaylistCatalog`, `CustomPlaylistCatalog`, and `SourceValidator` own user
  M3U/custom channel persistence and validation. IPFS content is not a
  distinct source type: users add a gateway HTTP URL (e.g.
  `http://127.0.0.1:8080/ipns/<name>/list.m3u`) as a regular M3U source.
- `ConnectedClientsClient`, `HealthClient`, and `ChannelStatusClient` query the
  running proxy/status endpoints.
- `ProxyExposure` owns local vs LAN exposure. The local proxy port is `8888`;
  server mode switches the native proxy listen host from `127.0.0.1` to
  `0.0.0.0`. `IpfsSettings` reuses this same LAN switch for the IPFS gateway
  (default port `8080`); the IPFS RPC API (`5001`) and swarm (`4001`) are
  never affected by LAN mode.
- `app/src/main/cpp/` contains the JNI boundary and CMake config. CMake builds
  `httpaceproxy_core` as a static library and `httpaceproxy_jni` as the shared
  Android library.
- `app/src/main/cpp/httpaceproxycpp/` contains the C++ HTTPAceProxy core:
  Ace client protocol, HTTP server, proxy handlers, plugins, playlist
  generation, broadcast streaming, JSON, and utilities. `ts_probe.cpp` is the
  transport-health probe: one per upstream, fed by the existing reader thread,
  exposed as the `streams` array of `/status` and
  `/stat?action=get_clients`.
- `app/src/main/assets/aceserve/main_android.py` is shared; the per-ABI
  AceServe zips live in `app/src/arm64/assets/aceserve/arm64-v8a/` and
  `app/src/armv7/assets/aceserve/armeabi-v7a/` — flavor-specific source sets,
  not `main`, so each ABI's build only packages its own zip (see "arm64" /
  "armv7" / "universal" product flavors below).
- `app/src/main/jniLibs/<abi>/libipfs.so` is the kubo (IPFS) binary for
  `arm64-v8a` and `armeabi-v7a`. It is generated by `tools/fetch-kubo.sh`, not
  committed to git, and required before `:app:assembleDebug`/`assembleRelease`
  (`:app:preBuild` fails with a clear message otherwise). It stays in `main`;
  each flavor's `ndk.abiFilters` (not `main`'s, which must stay unset — see
  the comment in `app/build.gradle.kts`) decides which ABI's copy gets
  packaged.
- The app builds three product flavors on the `abi` dimension: `arm64`
  (`arm64-v8a` only), `armv7` (`armeabi-v7a` only), and `universal` (both).
  This is what keeps the kubo binary and the AceServe zip from doubling up
  ABIs that a given install can never use — `assembleUniversalDebug` is the
  one to use for day-to-day local development; `assembleDebug`/
  `assembleRelease` are aggregate tasks that build all three.
- `app/src/main/assets/httpaceproxy/http/` is the bundled HTTPAceProxy web UI.
  Treat minified third-party files like jQuery, Bootstrap, and Popper as
  vendored assets.
- `app/src/main/res/values/` and `app/src/main/res/values-es/` must stay in
  sync for user-visible strings.

## Build And Verify

Build the bundled IPFS (kubo) binaries once before the first Gradle build
(`arm64-v8a` needs only Go; `armeabi-v7a` needs the Android NDK for cgo
linking — `android/arm` requires it, enforced by the Go toolchain itself):

```sh
tools/fetch-kubo.sh
```

Use JDK 17 plus the Android SDK/NDK expected by Gradle:

```sh
JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home" \
ANDROID_HOME="$HOME/Library/Android/sdk" \
./gradlew :app:assembleUniversalDebug
```

Useful commands:

```sh
./gradlew -q :app:printVersionName
./gradlew -q :app:printVersionCode
./gradlew :app:assembleUniversalDebug
./gradlew :app:lintUniversalDebug
```

Install and open the debug build on a connected device with:

```sh
$ANDROID_HOME/platform-tools/adb install -r app/build/outputs/apk/universal/debug/app-universal-debug.apk
$ANDROID_HOME/platform-tools/adb shell am start \
  -a com.streamvault.plugin.hap.CONFIGURE \
  -p com.streamvault.plugin.hap
```

JVM and Robolectric tests live in `app/src/test` (240 tests; the layout tests
drive the real views with real key events). There are no instrumented
`androidTest` sources: anything that needs a running box is verified by script
(`tools/device-check.sh`) and recorded in `docs/Tv-Verification-Checklist.md`.

```sh
./gradlew :app:testUniversalDebugUnitTest
./gradlew :app:lintArmv7Debug
```

For behavioral changes, run at least `:app:assembleUniversalDebug` and the
suites above, then do a device smoke test for the affected flow.

### Native unit tests

The pure helper layer (`app/src/main/cpp/httpaceproxycpp/src/util.cpp`) has a
host-side GoogleTest suite in `native-tests/`. It compiles the same source that
ships in the APK, without `HTTPACEPROXYCPP_ANDROID`, so `log_line` falls back to
`std::cerr` and no Android SDK is needed. It covers URL parsing and
`path_is_safe_relative`, the guard that keeps `/stat/<path>` from serving files
outside the bundled `http/` directory.

```sh
cmake -S native-tests -B build/native-tests -DCMAKE_BUILD_TYPE=Release
cmake --build build/native-tests -j
ctest --test-dir build/native-tests --output-on-failure
```

Nothing under `native-tests/` is packaged into the app.

### On-device measurement

`tools/device-check.sh` collects reproducible measurements straight from the
device: hardware facts, per-process RSS, thread counts, socket counts, and
start/stop leak checks. Run the same scenario before and after a change instead
of estimating.

```sh
tools/device-check.sh facts
tools/device-check.sh install app/build/outputs/apk/armv7/debug/app-armv7-debug.apk
tools/device-check.sh scenario
tools/device-check.sh leak-check
```

On WSL2 there is no USB sysfs, so the device is only reachable through a
Windows-side adb; pass it explicitly:
`ADB=/mnt/c/Users/<user>/hap-tools/platform-tools/adb.exe`.

Debug builds also carry `HapDebugControlActivity`, declared only in
`app/src/debug/AndroidManifest.xml`, so the runtime can be driven from a script
instead of the D-pad. Release builds contain neither the class' manifest entry
nor an exported control surface:

```sh
ADB=... tools/device-check.sh control start
ADB=... tools/device-check.sh control status
```

## Interface

`HapConfigActivity` is now a shell, not the interface itself. Its root is
`res/layout/activity_hap.xml`: a 300dp navigation rail with five sections — Inicio,
Canales, Fuentes, Conexiones, Ajustes — beside a content `FrameLayout`, plus a key-hint
footer. `HomeScreen` builds the home content; `HapSections` maps each section to the panel
builders it hosts and is pinned by a test, so every panel builder must be called exactly
once. `ConnectPlayerActivity` is the separate how-to-watch screen the home card opens; it is
`exported="false"` and is not a launcher entry.

Sections are built once and revealed by visibility alone. Never rebuild a section to refresh
it: set text on the views that changed. `removeAllViews()` remains in eight list renderers and
is a known cost, not a pattern to copy.

The design system lives in `res/values/colors.xml`, `dimens.xml` and `styles.xml`
(`TextAppearance.HaP.*`), with focus rendered by the `res/drawable/bg_*` state lists so it
survives refreshes. TV dimens are in `values-w600dp`, not `values-sw600dp`: a TV box reports
960x540dp, where a smallest-width qualifier would never match. Rail selection and rail focus
are separate states and must both stay visible.

On-device behaviour is not established by a build. `docs/Tv-Verification-Checklist.md` lists
what must actually be observed with the remote before any interface claim is treated as true.

## Change Rules

- Keep version data synchronized across `app/build.gradle.kts`,
  `AndroidManifest.xml`, `README.md`, and `docs/Changelog.md`.
- Keep StreamVault metadata aligned with the supported API surface:
  `provider.m3u`, `playback.prepare`, `cast.rewriteUrl`, and
  `configuration.activity`.
- Do not advertise `configuration.schema` unless a complete host-rendered schema
  is intentionally implemented. The native activity is the source of truth.
- Keep `HapConfigActivity` exported for
  `com.streamvault.plugin.hap.CONFIGURE`, but do not add launcher or Leanback
  launcher intent filters. The plugin should stay hidden from app drawers.
- Put user-visible text in Android resources and update both English and Spanish
  resources together.
- Public builds must not ship hardcoded playlist sources. Sources are
  user-managed M3U lists plus the generated `Custom` source.
- Preserve M3U validation semantics: HTTP/HTTPS URL, `#EXTM3U` header, M3U
  channels, and at least one AceStream-like target.
- Changes that affect Cast/LAN playback should go through `ProxyExposure` and
  `HapBridge`; enabling server mode should restart the proxy if it is running.
- Changes that affect runtime startup must respect `ProxySupervisorService`'s
  lifecycle, foreground service notification, `ServiceState`, and readiness
  checks for AceServe and HTTPAceProxy. IPFS runs on its own supervisor
  thread with its own `ServiceState` fields (`ipfs*`) and must stay
  independent: a failure starting/stopping IPFS must never affect
  AceServe/HTTPAceProxy state or vice versa.
- Native changes should keep C++20, the Android compile definition
  `HTTPACEPROXYCPP_ANDROID=1`, and the JNI library link option
  `-Wl,-z,max-page-size=16384`.
- Do not casually edit bundled ABI zips, `libacepython.so`, `libipfs.so`, or
  vendored minified web libraries. Treat them as binary/vendor inputs unless
  the task is explicitly about refreshing them (for `libipfs.so`, bump
  `KUBO_VERSION` in `tools/fetch-kubo.sh` and rerun it).

## Release Notes

The GitHub workflow `.github/workflows/build-apk.yml` builds signed release APKs
on tags or manual dispatch. Release tags must match `versionName` with an
optional leading `v`. Signed releases require the Android signing secrets used
by the workflow.
